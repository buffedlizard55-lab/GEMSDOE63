Why an earlier download was rejected

A previous session's file was rejected by the form with "Predicted values must be in range [0, 1]". The rule is a single float32 layer with values between 0 and 1. Two things in this repository exist specifically to stop that recurring:

  • raster_io.write_submission() refuses to write a file whose values leave [0, 1], that contains a non-finite value, or whose shape differs from the template. It raises rather than producing a file the form will reject.
  • validate.validate_submission() then re-opens the written file from disk and re-checks it, including CRS, shape and geotransform compared byte-for-byte with the organizer's template. The result above is that re-check, not a promise.

This file is written all-finite with zeros outside the survey footprint. NaN is permitted outside the bounds by the rules, but an all-finite file removes an entire class of validator disagreement, and sibling repositories have scored with exactly this convention.
