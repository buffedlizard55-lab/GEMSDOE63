Method

1. The metric, and the two identities that drive the design

From page 967, with R = 300 m = 3 px and k(d) = max(1 - d/R, 0):

TP_w = sum_g  max_(x: d(x,g) <= R)  p(x) k(d(x,g))
FP_w = sum_(x: p(x)>0)  p(x) [ 1 - max_g k(d(x,g)) ]
FN_w = sum_g  [ 1 - max_(x: d(x,g) <= R)  p(x) k(d(x,g)) ]
DTI  = TP_w / ( TP_w + 0.2 FP_w + 0.8 FN_w + eps )

Identity 1. Every ground-truth pixel contributes max + (1 - max) = 1 across the TP and FN terms, so FN_w = |G| - TP_w, and with N = |G|:

DTI = TP_w / ( 0.2 (TP_w + FP_w) + 0.8 N )

Identity 2. Adding mass p with realised kernel weight k moves TP_w by k p and FP_w by (1-k) p, so the denominator moves by exactly 0.2 p and

the score rises  <=>  k > 0.2 * DTI

A dot that lands on a truth pixel pays no false-positive penalty at all, because FP carries the factor (1 - kmax) and kmax = 1 there. That single fact is why sparse, accurately placed emission beats dense emission.

A refinement this lane contributes. Identity 2 is a necessary condition, not a sufficient one, once emission already exists. Because TP_w is a maximum per truth pixel, the credit a new set A actually earns is sum_g [max(k_E, k_A) - k_E], which is strictly less than sum_(x in A) k_x wherever existing emission already covers that truth pixel. The false-positive cost, by contrast, is incurred in full. So the naive rule "emit if k > 0.2 DTI" over-states the benefit of widening, and the empirical greedy prune below is what actually decides the width. This is measured, not argued: see the per-band table on the results page, where every band out to 4 px clears the naive bar and bands 3-7 are still rejected by the exact metric.

2. Why emission is binary

For a pixel with realised weight k above the bar, the interior optimum in p is p* = (k - 0.2 DTI) D / (0.2 k) with D = TP_w / DTI. At any realistic operating point D is in the thousands, so p* >> 1 and the cap p = 1 binds. Binary emission at 1.0 is therefore optimal, and the only real choice left is which pixels. That is asserted numerically in tests/test_metric.py.

3. The scored domain

The organizer's masking rule (thread 11516) is applied pixel-exactly: the scored domain is footprint & ~catalogue. Known-fault pixels are removed from every sum, so emission placed on a mapped trace can neither help nor hurt — which is why the ribbon excludes the catalogue pixels themselves.

Every rate is calibrated to a measurement or an organizer statement; none is invented.

Truth is always clipped to the scored domain, so no world ever contains a pixel the organizer's mask would remove.

5. Selection and pruning

With loss L = 1 - DTI, CVaR at confidence beta is the mean of the worst 1 - beta fraction. Rockafellar & Uryasev show CVaR_beta(L) = min_zeta [ zeta + E(L - zeta)+ / (1 - beta) ]; both routes are implemented and tests/test_cvar asserts they agree, so the tail number is not taken on trust. Candidates are ranked by

objective = (1 - lam) * mean(DTI) + lam * CVaR_worst(DTI),   lam = 0.5000

then pruned greedily: each distance band is offered up in turn and dropped if removing it improves the objective. The unit of pruning is the band, not the pixel — pixel-level greedy on a several-hundred-thousand-pixel emission is O(N) full-metric evaluations and is not tractable, and the band is the smallest grouping that answers the question the pruning is for.

6. Leakage canary

The only signal this lane uses is distance-to-catalogue, so that is what is tested alone on the holdout. Measured mean AUC: nan against a gate of 0.90. Below the gate — but read the caveat in the run card: at high phi the worlds are displaced copies of the catalogue, so the canary is only informative because the ensemble spans phi down to 0.15.
