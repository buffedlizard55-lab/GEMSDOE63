2. Why it scores what it scores — the arithmetic

From the published metric, with N = |G| (identity 1 on the method page):

DTI = T / ( 0.2 T + 0.2 S + 0.8 N )
T = 0.058829*S + 0.235314*N

Two consequences, both computed rather than asserted:

  1. The score certifies a floor on recall. Setting S = 0 gives the best case, so T/N ≥ 0.2353. The artifact demonstrably found at least 23.5% (kernel-weighted) of a truth set that is defined as the faults absent from USGS/INGENIOUS. No instrument in this repository can produce that number, because the only local truth is the catalogue.
  2. The marginal bar for adding a dot is low. A dot raises the score iff its realised kernel weight exceeds 0.2 × DTI = 0.0556. Any dot with a better than 5.6% chance of landing within 300 m of a hidden new fault helps. That is why 37,654 basin-wide dots is a rational design and not spam.

3. The finding that matters most for this repository

94.2% of this artifact's dots are more than 3 px from any mapped fault, and none sit on a catalogue pixel. The group's best-scoring artifact is almost entirely off the catalogue — it is a lineament-detector field, not a catalogue-adjacent ribbon. That is the opposite bet to the one this lane makes, so it has to be confronted rather than ignored.

If the scoreable truth were confined to within 300 m of the mapped catalogue, this artifact could only have reached 0.2778 if the entire truth set were <= 18,807 pixels, about 31% of the catalogue's own pixel count. A larger truth set makes that impossible, which would mean a substantial share of the truth lies further out than 300 m -- exactly where 94% of this artifact's dots are.

Stated as a necessary condition, with every assumption on the table:

  • If the scoreable truth lay entirely within 300 m of the mapped catalogue (this lane's hypothesis), then the 35,483 far dots all have kmax = 0, so S ≥ 35,483; and no set of 2,171 near dots can earn more than 6,513 of T (3.0 per dot is the competition's own worked example). Together with the owner-reported score that forces N ≤ 18,807 truth pixels — about 31% of the catalogue's 60,988 pixels.
  • That is possible but restrictive. If the real truth set is larger, the far dots must be earning credit, and the truth extends well beyond 300 m from the catalogue.

What this repository does about it. The label-world ensemble does not assume the answer. Its phi parameter — the share of truth that is newly mapped geometry of an existing system — is drawn per world across 0.15–0.95, and the remainder is unrelated new structure scattered at the observed density, i.e. far from the catalogue. The CVaR objective is tail-penalised over that whole range, so the selected emission is the one that survives both readings. The phi-stratified table on the results page shows how each candidate moves as phi moves; it is the honest answer to "which bet is this?".

4. Can a higher-scoring submission be generated? Ranked by expected gain

  1. Raise per-dot credit, not dot count. The bar is ~0.056 and the metric's true-positive term is a maximum per truth pixel, so extra dots in the same place earn nothing while still paying false-positive cost. Better-placed dots are the only lever that does not saturate.
  2. Use the layers nobody has used. The geodetic strain bands (second invariant, shear, dilatation) are in the provided stack and, so far as the registry shows, no prior artifact uses them as a primary detector. See hypotheses.
  3. Do not optimise the local catalogue proxy. It cannot see the target population. Sibling repositories report it anti-selects novelty.
  4. Change one factor per slot. The submission page is the only organizer-confirmed channel; a slot that changes density and detector together cannot be interpreted afterwards.

5. What this page does not claim

It does not claim 0.2778 is reproducible, or that any file here is comparable to it. The recall floor in §2 is a necessary condition implied by an owner-reported score, not a measurement of the artifact against the hidden test faults — which are not available in this sandbox by the organizers' explicit policy (thread 11527).
